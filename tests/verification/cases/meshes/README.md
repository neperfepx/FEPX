# Verification meshes

All regenerated on 2026-11-05 with Neper 5.0.1-731-devel and Gmsh 4.15.2 with Netgen (step 9.20,
ROADMAP D113; before, 2026-11-02 with 5.0.1-713-devel, D110), except the annuli. A mesh that runs on 2 ranks has a copy `<mesh>_part2.msh`: the orientation variants of sx2
are made the same way from `sx2_part2.msh`, the periodic ones with the same commands and `-part 2`.

`sx2_rotx45.msh`, `sx2_rotx90.msh`: the single-crystal mesh `tests/regression/cases/meshes/sx2.msh`
(a 2-cell tessellation of the unit cube whose cells have one orientation; see that directory's
`generate_meshes.sh`) with its `$ElsetOrientations` section replaced by a rotation of 45° and 90°
about x, given to both cells, in `axis-angle:passive`:

```
$ElsetOrientations
2 axis-angle:passive
1 1.0 0.0 0.0 45.0
2 1.0 0.0 0.0 45.0
$EndElsetOrientations
```

`sx2_id.msh` (step 6.2): the same with the identity orientation (`1 1.0 0.0 0.0 0.0` for both
cells), i.e. the cubic axes along x, y, z (the fcc [001] flow-stress case).

They replaced `sx_rotx45.msh` / `sx_rotx90.msh` (the single-cell `sx.msh` with the same sections)
on 2026-10-09 (ROADMAP step 3.3 review, Q12). Used by the cases listed in `../../README.md`.


`annulus_<type>_n<N>.msh` (`type` tet10 or hex20, N = 4, 8): structured quarter annuli for the
Lamé verification (dev/theory/addendum_lame.md §3; ROADMAP D43 (4)): a = 1, b = 2, h = 0.25,
N cells radially, 2N around, 1 through the thickness; mid-nodes on the curved geometry; node sets
x0, y0, z0, z1, inner, outer; one elset, orientation rodrigues 0 0 0. Generated by
`generate_annulus.py` (Python 3, no other dependency):

```
for t in tet10 hex20; do for n in 4 8; do
  python3 generate_annulus.py --type $t --nr $n --nt $((2*n)) --nz 1 annulus_${t}_n${n}.msh
done; done
```

`sx2_off100.msh` (step 7.2): `sx2_id.msh` with both cells rotated by 5° about [1 2 0]
(`1 0.4472135955 0.8944271910 0.0 5.0`, axis-angle:passive), a crystal slightly off the cube
orientation, as Barton et al. (2013) load their single crystals "slightly off-[100]" (case
`fepx_bcc_km_barton`). Made with `sed` on the `$ElsetOrientations` lines of `sx2_id.msh`.

`periodic_box_2x1x1.msh` (step 8.3, CHANGES.md C72): a periodic 4-cell tessellation of a
2 × 1 × 1 box, 10-node tetrahedra, regularized (`-reg 1`) since step 9.20 (`_part2` with `-part 2`):

```
neper -T -n 4 -id 1 -domain "cube(2,1,1)" -periodicity all -reg 1 -o tess
neper -M tess.tess -order 2 -part 0 -rcl 1.4 -o periodic_box_2x1x1
```

Without `-reg 1` the tessellation's tiny edges gave sliver tets (880 tets, median/min corner-tet
volume 34363, quality 6√2·V/max_edge³ ≥ 0.0148, 22 below 0.05) on which
`fepx_periodic_v1_full`'s nine imposed components did not converge (the outer residual grew
until CG reached its iteration limit; ROADMAP 9.20 item 5), as `poly_periodic` in step 9.19.
Now 168 tets, median/min volume 12.2, quality ≥ 0.044 (median 0.304).

`periodic_cube.msh` (step 8.3b): a periodic one-cell tessellation of the unit cube (planar faces,
the "regular box" of the periodic verification, addendum §5), 10-node tetrahedra; its three drive pairs share the corner node 1:

```
neper -T -n 1 -id 1 -periodicity all -o cube_periodic
neper -M cube_periodic.tess -order 2 -rcl 1.5 -part 0 -o periodic_cube
```

`periodic_cube_x.msh` (step 8.3b): a two-cell tessellation of the unit cube periodic along x only
(its relations all have the vector (+-1, 0, 0)), for the error test of a mesh not periodic along
all three axes (the one-cell mesh of `-periodicity x`, which older Neper could not mesh, is not used):

```
neper -T -n 2 -id 1 -periodicity x -o cube_periodic_x
neper -M cube_periodic_x.tess -order 2 -rcl 1.5 -part 0 -o periodic_cube_x
```
